# Контроль записи и просмотр спорных эпизодов

Функция включается `INTEGRITY_ENABLED=true` только для **создаваемых после этого интервью**.
Значение сохраняется в `workflow_interviews.integrity_enabled`; смена конфигурации не меняет
старые приглашения и интервью. По умолчанию флаг выключен. Контроль не запускается в практике.

Сохраняется существующий FastAPI / PostgreSQL / MinIO стек. Контроль использует единственную
модель `google/gemini-2.5-flash` через тот же `OPENROUTER_API_KEY`, без резервной модели,
отдельного брокера или дополнительных модельных провайдеров. Существующие оценка ответов,
STT и озвучивание вопросов продолжают использовать свои настройки.

## Запуск

В Compose FFmpeg и FFprobe устанавливаются в образ backend. Оставьте
`INTEGRITY_WORKER_ENABLED=true`: worker обрабатывает задания и автоматически удаляет
исходные порции и подготовленные integrity MP4 через 30 дней. Удаление кандидата также
удаляет его integrity-данные и файлы. Для запуска без Docker установите FFmpeg/FFprobe
или задайте `INTEGRITY_FFMPEG_PATH` и `INTEGRITY_FFPROBE_PATH`.

Перед включением проверьте хранилище с настройками целевого окружения:

```bash
# Из корня репозитория; .env должен содержать S3-параметры Compose.
backend/.venv/bin/python backend/scripts/check_integrity_storage.py
```

Сценарий создаёт один временный объект, проверяет подписанную ссылку, OPTIONS CORS,
GET Range 206, точные байты, Content-Range/Accept-Ranges и 416 для неверного диапазона,
затем удаляет объект. Ссылки и ключи доступа не выводятся. Публичный endpoint S3 должен
быть доступен браузеру; нельзя переписывать hostname уже подписанной SigV4 ссылки.
В Compose `MINIO_API_CORS_ALLOW_ORIGIN` получает `CORS_ORIGINS`. Для другого S3 доступны
правила `S3ObjectStorage.configure_media_cors`; настройте их при подготовке bucket.

На внешнем домене нужны HTTPS и корректные разрешения camera/microphone/display-capture.
Кандидат явно выбирает полный монитор. Выбор окна/вкладки отклоняется. Если браузер не
сообщает `displaySurface=monitor`, он не может подтвердить обязательное условие.
Для SQLite используйте один процесс API; в PostgreSQL глобальная advisory lock обеспечивает
единственный worker даже при нескольких процессах API. Не выключайте worker для старых
сессий, отключая флаг создания новых интервью: иначе остановится и очистка по сроку хранения.

## Запись и время

Камера с микрофоном и экран записываются непрерывно, включая озвучивание вопроса,
ожидание ответа, загрузку и промежутки между вопросами. Каждые 10 секунд сохраняются
порции с идентификатором потока, порядковым номером и диапазоном относительно серверной
сессии. Любой перезапуск MediaRecorder создаёт новый поток. IndexedDB хранит неподтверждённые
порции и события и повторяет отправку с теми же идентификаторами. Finish отправляется после
порций. Технические события не являются решениями о нарушении.
Если браузер пропал из сети до Finish, сервер показывает незавершённую загрузку и принимает
порции после восстановления. Он не запечатывает неполный поток по таймауту heartbeat.

При остановке обязательного захвата текущий ответ сохраняется. Сервер не выдаёт следующий
вопрос ни через state/briefing, ни через повторную отправку ответа, ни через endpoint озвучки.
Последний ответ и завершение интервью не требуют восстановления уже ненужного захвата.
Heartbeat устаревает через 30 секунд. При восстановлении выдача вопросов продолжается.
Будущие вопросы остаются на сервере. Уточняющие вопросы могут просить объяснить собственное
решение или адаптировать его к изменению одного условия, сохраняя прежний лимит уточнений.

MediaPipe Face Landmarker 0.10.32 и модель загружаются с сервера приложения, а не с CDN.
Классический Web Worker выполняет CPU-инференс максимум 5 раз в секунду. После калибровки
локально выделяются только длительные слабые сигналы: отсутствие лица, изменение положения
головы и глаз относительно диапазона калибровки. Необработанные landmarks не передаются.
Неуспех калибровки/worker отмечается как техническая недоступность и не отменяет интервью.

## Очередь, модель и доказательства

Отдельные SQLAlchemy-таблицы хранят сессии, события, порции, готовые потоки, задания,
наблюдения и человеческие решения. Схема создаётся аддитивно вместе с текущей схемой проекта.
Интервалы имеют длину до 120 секунд, шаг 115 секунд. Первичный вызов допускает максимум
два повтора. Завершённые интервалы повторно не вызывают модель; результат успешного вызова
сохраняется до обработки findings, чтобы восстановление после сбоя не повторяло оплаченный вызов.

Один запрос содержит доступные видео камеры и экрана, звук микрофона, расшифровку и события
интервала. Весь наблюдаемый контент считается недоверенными данными, включая инструкции в
речи и документах. Модели не передаются инструменты; её ответ не может менять состояние
интервью, баллы или решения. Только whitelist полей проходит серверную валидацию.
Ссылки в findings принимаются исключительно как ID существующих принадлежащих интервью
материалов, с диапазонами внутри записи и анализируемого интервала. Текст модели не может
задавать URL. Пересекающиеся наблюдения одного типа объединяются через границы интервалов.

Для каждого непрерывного recorder-потока один раз собирается MP4 H.264/AAC с faststart.
Timeslice-порции WebM соединяются как байты одного контейнера. Если начальная порция или
часть последовательности отсутствует, недекодируемый остаток не выдаётся как готовая запись.
Нет отдельных постоянных видеофайлов для findings: временные аналитические нарезки удаляются
в `TemporaryDirectory`, даже после ошибки. Списки воспроизведения и внешние протоколы
не принимаются FFmpeg при чтении загруженного контейнера.

## Просмотр

`integrity-review.tsx` встроен в человеческий разбор и использует общий `evidence-player.tsx`.
Старые выделенные фрагменты ответов используют тот же плеер. В карточке показаны источник,
наблюдение, причина проверки, ограничения, обычные объяснения и длительность. Если запись
недоступна или удалена, отображается «Видео этого интервала отсутствует» без кнопки просмотра.

Плеер начинает с эпизода ±5 секунд и синхронизирует потоки по серверным смещениям. Камера
задаёт время; расхождение экрана свыше 250 мс корректируется. Звук доступен только у камеры.
Общие элементы управления включают Play/Pause, перемотку, скорость, повтор, контекст ±10 секунд,
весь ответ и разворачивание экрана. При буферизации оба потока останавливаются. В пробелах
показывается отсутствие записи, а не предыдущий кадр. При ошибке ссылки manifest запрашивается
заново с сохранением позиции. При закрытии освобождаются видео и таймеры.

Подсветка слов использует только существующее выравнивание STT и фактически записанное начало
ответа. Без этого текст отображается без синхронизации. Весь ответ включает связанный вопрос;
межвопросный эпизод раскрывает доступный контекст записи. Выдача каждой подписанной ссылки
проверяет владение кандидатом со стороны рекрутера. Ссылки живут 10 минут, включая локальное
файловое хранилище; playback-ответы имеют `Cache-Control: no-store`.

Решения «Объяснено», «Нарушение подтверждено», «Нужно уточнить» сохраняются отдельно по ревьюеру.
Для подтверждения обязателен непустой комментарий. Наблюдения и решения по ним не меняют
балл компетенций или ранее записанное независимое человеческое решение. Экран отдельно
показывает покрытие записью, анализом, сообщённую OpenRouter стоимость и незавершённые задания.
Неизвестная стоимость не выдаётся за полный нулевой расход.

## Проверки

```bash
cd backend
.venv/bin/python -m pytest
.venv/bin/python -m ruff check .

cd ../ui
pnpm exec tsc --noEmit --incremental false
pnpm run lint
pnpm run build
node --experimental-strip-types --test tests/evidence-timeline.test.mjs
node --test tests/integrity-capture.test.mjs
```

Backend-тесты проверяют доступ чужого кандидата/рекрутера, потерю/восстановление захвата,
последний ответ, неизменность флага, идемпотентность, ложные ссылки/границы, prompt injection,
объединение пограничного эпизода, лимит повторов, checkpoint, TTL и локальные Range/CORS.
`test_integrity_ffmpeg.py` делает реальный WebM → faststart MP4 → аудио/видеонарезку; без
FFmpeg/FFprobe он явно пропускается. Живой MinIO проверяется отдельным сценарием выше.

До запуска с реальными кандидатами дополнительно пройдите интервью в целевых браузерах
с реальными разрешениями камеры/экрана, остановкой захвата, перезагрузкой вкладки и offline.
API-тесты используют детерминированные модели и не тратят средства OpenRouter.
Проверка плеера в Chromium с синтетической записью описана в `ui/tests/README.md`.
